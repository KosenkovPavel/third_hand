# Архитектура

## Слои

```
                 ┌─────────────────────────────────────────────┐
                 │            Расчётное ЯДРО (src/*.py)        │
                 │  portfolio / accounting / xirr / iis /      │
                 │  rebalance / risk / forecast / picks /      │
                 │  stress_test / montecarlo / signal_journal  │
                 │  ── только каноническая модель, без SDK ──   │
                 └───────────────▲─────────────────────────────┘
                                 │ протоколы (ABC)
        ┌────────────────────────┼─────────────────────────────┐
        │  Провайдеры            │                             │
        │  tinkoff (текущий) · sber/alfa (будущие)             │
        └────────────────────────┴─────────────────────────────┘

   ┌──────────┐  ┌──────────┐  ┌───────────────┐  ┌──────────┐
   │  CLI     │  │  TUI     │  │  MCP-сервер   │  │  REST    │
   │ (флаги)  │  │ (меню)   │  │ (для агентов) │  │ (отлож.) │
   └──────────┘  └──────────┘  └───────────────┘  └──────────┘
```

## Поток данных

```
провайдер (SDK) → адаптер → каноническая модель → ядро (вычисления)
   → ReportData (датакласс) → фасад (rich / JSON) → пользователь / агент
```

Ключевой разрез: **ядро не знает, кто его рендерит; фасады не считают**.
`ReportData` — единый контракт между вычислением и отображением: все три
фасада (CLI, TUI, MCP) строят один и тот же отчёт через `build_report()`
/`build_multi_report()` и рендерят по-разному.

## Провайдеры

Три протокола вместо одного «толстого» интерфейса
(`src/providers/protocols.py`):

| Протокол | Ответственность |
|----------|-----------------|
| `AccountClient` | счёт, портфель, операции, дивиденды, купоны |
| `MarketDataClient` | инструменты, свечи, цены, фундаменталки |
| `AnalyticsClient` | консенсус аналитиков, инсайдеры, RSI |

Домен не импортирует SDK брокера — только через адаптер
(`src/providers/tinkoff.py`). Новый брокер = новый адаптер, ядро не трогаем.

## Ключевые решения (пересказ ADR)

- **ADR-0001 · Вычисление отдельно от рендера.** Ядро возвращает датаклассы,
  фасады рисуют. Поэтому CLI/TUI/MCP делят одну логику без копипасты.
- **ADR-0002 · Абстракция брокера.** Три протокола, интерфейс-сегрегация —
  чтобы подключение Сбера/Альфы не трогало расчёты.
- **ADR-0003 · Каноническая модель данных.** Одна модель портфеля
  (`Position`, `PortfolioSnapshot`), провайдер приводит всё к ней (включая
  НКД-математику).
- **ADR-0004 · MCP как интерфейс для агентов.** Агенту отдаются готовые
  вычисления, а не сырые данные — сырые даёт официальный MCP брокера.
- **ADR-0005 · TUI на rich/Textual.** Дружелюбный интерактив без аргументов
  командной строки; запуск без флагов = TUI.
- **ADR-0006 · Синхронное ядро, асинхронные границы.** Вычисления синхронные;
  сеть параллелится на границах (ThreadPoolExecutor при сборке отчёта).
- **ADR-0007 · JSON-хранилище.** Профиль, история, журналы — JSON в `data/`
  (не коммитится); бэкапы перед перезаписью.
- **ADR-0008 · Провайдер из конфига.** Реестр провайдеров через конфигурацию,
  а не if-ы по коду.
- **ADR-0009 · Rust-переписывание отложено.** Python-версия — «золотой эталон»
  финансовой корректности; Rust v2 — после роадмапа.
- **ADR-0010 · Мультисчёт.** Отчёт умеет объединять несколько счетов
  (брокерский + ИИС) в один снапшот, налоговая логика — по счёту ИИС.
- **ADR-0011 · Конфигурируемый скоринг и онбординг.** Метрики рейтинга
  компаний настраиваются профилем; первый запуск — визард.

## Хранение данных

`data/` (вне git): `profile.json` (настройки пользователя), `portfolio.json`
(снимок), `history.json` (точки для графика), `recommendations_history.json`,
`signal_journal.jsonl`, `cbr_cache.json`, `backups/`. Шаблон со всеми полями —
`data/profile.example.json` (в репозитории).

## Тестовая стратегия

193 теста без сети: провайдер заменяется заглушками, каноническая модель и
вычисления проверяются детерминированно. TUI тестируется headless через
тестовый раннер Textual. MCP — прямым вызовом инструментов.
